# Render, measure and commit smells

2026-10-04. An audit of every react-ui and native-ui component, by six reviewers, for code that works only by accident of render, measure or commit timing (the smell behind native-ui SheetBase in 003-35 and 003-38). Feeds epic 005 (not yet filed); drains as its stories land.

## Verdict

72 findings: 17 visible, 22 fragile, 33 wasted renders. Themes: (A) a child tells its frame what it is after paint (Screen cover, Split lend and standAlone, Place floats, Thread fills and docks, the Shell measuring the toast frame), on both platforms; (B) sheets reset or close mid-dismiss (confirm typed text, Picker search, TextArea grow, a cell Picker unmounting its sheet, confirm mounting a commit late); (C) timers covering ordering (cell Escape blur, Table rAFs, Code and Picker rAF focus, copy reset, pending-bar and age never ticking); (D) measured text (FileRow path); (E) wasted renders (ActionBar and Button reset effects, unstable context values, Intl formatters, unmemoised markdown, diff and QR, Table hover and press state, both Table forms rendered).

Open decision for theme A: frames learn what children need up front (props or slots; recommended) or through layout effects. The Section rows, fields, busy and count registration (004-02) uses the layout-effect shape and is flagged fragile by the same audit.

## Findings

Severity, confidence and smell (1 two-phase sizing, 2 painting rides an incidental commit, 3 unnecessary renders, 4 effect misuse, 5 timers or measuring over ordering, 6 library state assumed), then the mechanism and the structural fix. Line numbers are at master 0b0075c.

- **plugins/native-ui/src/ui/components/split/index.tsx:413** (visible, confirmed, smell 4). Split pushes `standAlone(true)` (L413-417) and `lend(Details act)` (L404-412) into the Place or Screen with plain `useEffect`, which runs after paint. A Split mounted with `main` already set (deep link, or a list row navigating to a record) commits and paints a Place top bar with the Shell switcher and no Details act. The effect then sets `alone`/`lent` state in the Place, and the Place re-renders with the back chevron in the switcher's place and the Details icon appended. The top bar visibly changes one frame after first paint. Each push also costs a Place re-render, and the Place re-renders its whole subtree because `ActRoom` (see Place finding) is a fresh element. Fix: Use `useLayoutEffect` for both registrations, as lib/section.ts does for its registrations and Thread does for `fills`; the re-render then lands before paint. Better, drop the state-push: Place takes `alone` and `lent` as registrations read in render, the same host-object shape as SectionHost.

- **plugins/native-ui/src/ui/components/screen/index.tsx:43** (visible, confirmed, smell 4). Screen calls `cover(true)` in `useEffect`. The Shell first paints the pushed Screen with the tab bar still in flow and the column's bottom padding at 0. After paint `covered` flips, the tab bar unmounts, the content frame grows, and the `onLayout` -> `setFrame` -> toast re-measure chain runs. The tab bar flashes under every pushed Screen and the Screen's body resizes after first paint. The cleanup runs after paint on pop, so the tab bar reappears late. Place's `floats(true)` (place/index.tsx:454-458) has the same post-paint timing, so the toast room under a floating act lands a frame late. Fix: Switch both registrations to `useLayoutEffect` so the Shell's re-render commits before paint. Better, have the Shell derive `covered` from the route (is a Screen route current?) instead of having the child tell it.

- **plugins/native-ui/src/ui/components/place/index.tsx:492** (fragile, confirmed, smell 1). The body's container type depends on `fills`, which Thread sets in a layout effect: `<Scroll>` (L502) when false, a plain `<View>` (L495) when true. The Thread therefore mounts inside the Scroll, then Place re-renders and swaps the parent type. React cannot move the subtree between different parent types, so the Thread and all its children are unmounted and remounted. This happens before paint, but it is two-phase: a full mount, destroy and remount of every message and input, and any state the Thread or its children set in their first mount is lost. It also leaves `ThreadFills` as a context carrying a state setter, a loop of child -> parent state -> child remount. The `fills`/`alone`/`lent` pushes also mean Place re-renders on each child mount. Fix: Make the body one structure that does not depend on the child's type: always the same container, with the Thread laying itself out through flex (`flex-1`, `grow`) and `Scroll`'s `contentContainerStyle` keeping `flexGrow`. Or let the Place choose the form from a prop (`bleed`) and keep Thread out of the scroll by contract. Avoid a child-to-parent state loop that changes the parent's element type.

- **plugins/native-ui/src/ui/components/split/index.tsx:420** (fragile, confirmed, smell 3). The two `<Scroll>` branches of the `opened ? ... : ...` ternary sit at the same position with the same type and no key, so React reuses one native scroll view across list and record. The list's scroll offset (and keyboard-aware internal state) carries into the record and back, and the record may open scrolled partway down. Only `className` and `contentContainerClassName` change. Fix: Give each branch a distinct key (`key="list"` / `key="main"`) so each region has its own scroll state, or render one Scroll per region.

- **plugins/native-ui/src/ui/components/split/index.tsx:401** (fragile, suspected, smell 3). `open` is a latched state while the Sheet is driven by `sheet && open`. When `pane` or `main` disappears, `open` stays true. When the pane returns (select another record) the Details sheet pops open by itself. The state is a second source of truth next to the props. Fix: Reset it with the prop that scopes it: key the open state to the record (`key` on a child component) or clear it when `sheet` goes false.

- **plugins/native-ui/src/ui/components/shell/index.tsx:103** (fragile, confirmed, smell 1). Toast geometry is measured twice: the column's `onLayout` -> `setHeight` (L121) and the content frame's `onLayout` -> `setFrame` (L130), then converted to `{top: frame.y, bottom: height - frame.y - frame.height}`. The toast layer is absent until both have fired, and it moves after first paint whenever the banner grows or `covered` changes. The column height is redundant: the overlay is `absolute` in the outer View, and `frame.y` and `frame.height` already give its box. Fix: Drop the column `onLayout` and the `height` state and style the layer with `{ top: frame.y, height: frame.height }`. That removes one measure and one Shell re-render per layout. Longer term, express it without measuring by laying the toast layer out with the same column structure (an overlay sibling reserving the same insets and banner).

- **plugins/native-ui/src/ui/components/action-bar/index.tsx:67** (fragile, suspected, smell 4). `void ran.finally(...)` creates a derived promise that rejects when the act's promise rejects. That is an unhandled rejection, and `setRunning(false)` and `pend(false)` run only because finally fires, while the error is not surfaced to the caller. The bar stays correct but the rejection escapes. Fix: `ran.then(done, done)` (or `try/await/finally` in an async handler) and decide where the error goes.

- **plugins/native-ui/src/ui/components/pending-bar/index.tsx:721** (fragile, confirmed, smell 2). `now` is state seeded at mount and refreshed by a 1 s interval started in an effect. The bar's render (share, `clock(end - now)`) reads stale `now`: for the first second after mount, and for the first second after `until` appears or changes, it shows `end - mountTime` (a clock up to one second off and the fill at the wrong share). `start` is the mount time, not when `until` was given, so a later `until` makes the fill jump. The painted fill depends on the interval's incidental re-render, and each tick re-renders the whole bar including the Button. `pressed` (L725-728) is also state kept in sync with `blocked` by an effect. Fix: Read the time in render from a single clock source: a `useNow(until)` hook that returns `Date.now()` per tick and a fresh value on `until` change (state set during render or `useSyncExternalStore`). Drive the fill with a Reanimated width/transform from `start`/`until` on the UI thread and keep the 1 s tick only for the text. Derive `pressed` from `blocked` as in ActionBar.

- **plugins/native-ui/src/ui/components/section/index.tsx:241** (fragile, suspected, smell 1). A loading Section mounts its body to learn what it is (rows or fields), then swaps to skeleton fields in a layout effect: a two-pass mount before paint. When `loading` flips true again (refetch) the body unmounts and remounts, losing any child state (FormField inputs, uncontrolled Pickers) because the fields skeleton replaces `children`. The `fields` state is also derived from refs plus `loading`, mirrored into state by an effect. Painting depends on a layout-effect-driven re-render, and registration order is the thing that works by timing. Fix: Keep the body mounted and hide it (the `hidden` class already used for folding) while drawing the skeleton fields as a sibling, so state survives. Make `fields` a plain derivation (`loading && rows === 0 ? fields || 3 : 0`), with registrations held in the state they trigger rather than in refs.

- **plugins/native-ui/src/ui/components/group/index.tsx:310** (fragile, suspected, smell 3). Rows are keyed by array index (`key={index}`) even though `Children.toArray` already assigned each child a stable key. A conditionally rendered row or a list that changes order shifts every later row's state onto the wrong element (switches, pickers, expanded states), and the hairline classes follow the index. Fix: Key each wrapper by the child's own key (`isValidElement(row) ? row.key : index`) and keep index only for the skeleton rows.

- **plugins/native-ui/src/ui/components/shell/index.tsx:133** (waste, confirmed, smell 3). `ShellSwitcher.Provider value={switcher ? <SwitcherPick switcher={switcher} /> : null}` builds a new element on every Shell render, so the context value changes identity each time. Every Place consuming `ShellSwitcher` re-renders (and, through its fresh `ActRoom` element, its Split and their Scroll children) on every Shell state change: `covered`, `lifted`, `footing` (which fires on every Thread input height change), `height`, `frame`, `moreAt`, pathname. Fix: Memoize the element on `switcher` (`useMemo`) or pass `switcher` through context and let Place render `<SwitcherPick/>`. Splitting the toast-geometry state into its own small component would also stop the Shell re-rendering for it.

- **plugins/native-ui/src/ui/components/place/index.tsx:451** (waste, confirmed, smell 3). `footprint = act ? <FloatingActRoom /> : null` is a new element each Place render and is passed as the `ActRoom.Provider` value (L488). Every consumer (Split, and any other scrolling region) re-renders each time Place does, which happens on every `lent`/`alone`/`fills` push and on every Shell-driven switcher change. `lead`, `room` and the actions array are also rebuilt each render. Fix: Hoist `FloatingActRoom` to a module-level constant element (it takes no props), or provide a boolean `ActRoom` and have the consumer render `<FloatingActRoom/>`.

- **plugins/native-ui/src/ui/components/action-bar/index.tsx:54** (waste, confirmed, smell 3). `useEffect` calls `setPressed(new Set(filtered))` on mount and whenever `blockedKey` changes. It always returns a new Set, so it never bails out: every ActionBar renders twice on mount, a post-paint state update used only to prune derived state. `pressed` is state mirroring `blocked` props. `host` objects (L81) are also recreated per render, so each act's `ReasonHostContext` value changes every render and the Buttons re-render. Fix: Derive the pressed set: prune during render (`if (key !== seenKey) { setSeenKey(key); setPressed(prune) }`), or have the Button's reason host own its pressed flag and clear it when `blocked` goes undefined. Memoize the per-act host or key it on the act.

- **plugins/native-ui/src/ui/components/section/index.tsx:186** (waste, suspected, smell 3). `open` is seeded from `folded` once and then ignored. Changing `folded` (controlled expansion from a parent) does nothing, a mirrored-prop state. Each List in a Section also triggers three `setState`s (`wait`, `count`, `rows`) and a fresh `Map` per count change, and each re-renders the Section head. Fix: Treat `folded` as an initial value by contract (rename or document it as `defaultFolded`), or derive `open` from the prop when given. Batch count/wait into a single reducer state.

- **plugins/native-ui/src/ui/components/sheet/base.tsx, `onChange`** (visible, suspected, smell 2). Every sheet reaches the screen under reduced motion only through the commit that `BottomSheetModal`'s `onChange` → `setSettled` triggers. Reanimated 4.4.1 ships `USE_COMMIT_HOOK_ONLY_FOR_REACT_COMMITS: true`, so a value set at once reaches the screen only on the next React commit. A read of Reanimated's source: a deferred frame flushes right after the paused commit mounts, and `FORCE_REACT_RENDER_FOR_SETTLED_ANIMATIONS` would re-sync a stored value, so the value likely never reaches the registry or is reverted (`propsToRevert`, `performNonLayoutOperations`). Fix: diagnose on the harness with local builds only (`DISABLE_COMMIT_PAUSING_MECHANISM`, then `FORCE_REACT_RENDER_FOR_SETTLED_ANIMATIONS` off) and a reduced-motion case resizing an open sheet, then make the sheet paint without relying on an incidental commit.

- **plugins/native-ui/src/ui/components/text-area/index.tsx:54** (visible, confirmed, smell 1). `useEffect(() => grow?.(), [grow])` runs on mount and sets SheetBase's `tall` state. That flips enableDynamicSizing off and sets snapPoints to ['100%'] after the sheet has presented content-tall (the modal's children mount only once presented), so the sheet opens short and then re-snaps to full height after first paint. This is the same two-phase sizing as SheetBase's footer: a later-mounting child resizes the container. `tall` is also never cleared, so a wizard's next page without a TextArea stays full height. Fix: Declare the height up front instead of discovering it from a descendant's mount: a Sheet prop (e.g. `fit` or `tall` set by the caller, which knows it places a TextArea) feeding snapPoints and dynamic sizing before present(). Drop useSheetGrow and GrowContext, or at minimum make the signal render-synchronous.

- **plugins/native-ui/src/ui/components/picker/sheet.tsx:160** (visible, confirmed, smell 4). `close()` calls setSearch('') and then onClose(), also on swipe, scrim and a pick. The filter resets while the sheet is still sliding out, so the rows re-expand to the full list during the leave animation. With dynamic sizing the content height jumps mid-dismiss, and the search Input is cleared on screen as it leaves. Fix: Reset the search when the sheet opens, not when it closes: derive-on-render (`if (open && !wasOpen) setSearch('')`, the SheetBase page-reset pattern) so the closing frame keeps the filtered list. close() then just forwards onClose.

- **plugins/native-ui/src/ui/components/sheet/confirm.tsx:44** (visible, confirmed, smell 4). `useEffect(() => { if (!open) setTyped('') }, [open])` clears the typed name as the sheet starts dismissing. The field empties on screen during the slide-out, `blocked` flips back to the reason, and the act re-disables mid-animation (it commits an extra render after the one that closed it). It is an effect that sets state purely to reset. Fix: Reset on a new decision, not on close: track the entry id and clear `typed` during render when `entry.id` changes (`if (forId !== entry.id) { setForId(entry.id); setTyped('') }`). Do not key ConfirmSheet by id, because a queued second decision would then remount a still-open sheet.

- **plugins/native-ui/src/ui/components/input/index.tsx:99** (fragile, confirmed, smell 5). On Escape in a cell, `moment.cancel(value, onChange)` restores via a parent state update, then `requestAnimationFrame(() => input.current?.blur())` waits one frame so onBlur's `leave(value, commit)` sees the restored value and commits nothing. It works only if the parent re-renders within one frame. A slower parent (or a batch spanning frames) makes the blur commit the stale typed value. Fix: Remove the ordering dependency in commitMoment (packages/ui-core/src/commit.ts): make cancel() clear `atFocus` so a following leave() cannot commit, then blur synchronously. This is shared with the web, so the rAF disappears on both.

- **plugins/native-ui/src/ui/components/picker/base.tsx:59** (fragile, suspected, smell 6). In a table cell, closing the sheet calls `cell.done()` in the same handler as setOpenState(false). Table's `done` ends the edit, which unmounts PickerBase and its SheetBase while gorhom still holds the presented modal. The sheet vanishes with no leave animation (the non-cell path animates via dismiss(LEAVE)), and SheetBase's `held` ref is never cleared by an onDismiss. Fix: End the edit once the sheet has finished dismissing, driven by the sheet's own onDismiss. Expose an after-dismiss callback on PickSheet or SheetBase and call cell.done() there, not at the press.

- **plugins/native-ui/src/ui/components/input-otp/index.tsx:40** (fragile, suspected, smell 4). Mount focus is an imperative `useEffect` guarded by a read of global focus state (`TextInput.State.currentlyFocusedInput()`). Input does the same job declaratively with autoFocus. The effect runs after paint, so in a sheet the keyboard rises a frame behind the content; the guard reads global state, so the outcome depends on commit order against other inputs mounting in the same commit. Fix: Use `autoFocus` (as Input does via FieldFocus), or drive it from a FieldFocus-style context, so focus is part of the mount. Move the 'unless another input holds it' rule to the caller that knows.

- **plugins/native-ui/src/ui/components/message-input/index.tsx:95** (fragile, suspected, smell 6). `send` and `stop` call `textField.current?.focus()` after the act so 'the keyboard stays on the text'. - **plugins/native-ui/src/ui/components/slider/index.tsx:53** (waste, confirmed, smell 3). `width` is state set from onLayout but never read in render, only inside the pick handler, so every layout change re-renders the slider (one extra render on mount). `new Intl.NumberFormat(...)` is also rebuilt on every render, including each drag step, since onChange re-renders it per move. - **plugins/native-ui/src/ui/components/picker/sheet.tsx:148** (waste, confirmed, smell 3). - **plugins/native-ui/src/ui/components/message-input/index.tsx:153** (waste, confirmed, smell 3). - **plugins/react-ui/src/ui/components/sheet/confirm.tsx:35** (visible, confirmed, smell 4). The `if (!open) setTyped("")` effect (the same pattern as sheet/base.tsx:85-87, `if (!open) setTouched(false)`) runs as soon as `open` turns false.
